## Genuine 3D graphics update (r4)

- **87 unit tests pass**: the 69 existing mechanics tests and 18 new independent solid-geometry checks. The latter verify finite indexed vertices, unit normals, nondegenerate/outward-wound triangles, closed connected surfaces, true three-axis extent/volume, capped Pac-Man mouths including late death frames, and ghost skirt poses. They exposed and verified fixes for reversed winding on the mouth caps and ghost body.
- **14 graphics browser groups pass**, including the production bundle. Tests inspect actual nonplanar position/normal/index buffers, `drawElements` submissions and rendered GPU pixels; they also cover all four ghost colors, mouth direction/animation, frightened blue/white, eyes and house states, real scoring and GPU pellet removal, fullscreen/mobile rotation, WebGL loss/restoration and unavailable-context fallback. The visible main canvas is checked as well as the underlying GPU layer.
- The final source also passes all **23 existing browser checks and 15 fullscreen regression groups**, preserving input, pause/restart, player switching, persistence, complete responsive layouts and native/fallback fullscreen behavior.
- Normal initial board: **10,440 submitted triangles in 18 draw calls**, with 29 cached GPU meshes. Dots share one batch rebuilt only when the dot set changes. Pac-Man poses and ghost skirt variants reuse geometry. No rendering or model runtime dependency was added.
- The maze remains flat Canvas 2D. Real indexed, lit, depth-tested WebGL meshes are rendered into a transparent layer and synchronously composited over it. Fruit, HUD and intermissions remain 2D. A visible footer label distinguishes active **3D** from **2D fallback**; the latter is used only when WebGL is unavailable/lost. Restoring the context restores meshes without replacing the game.
- Engine, maze, level rules, shared actor types and fullscreen/view-controller source hashes match their pre-update baseline. Rendering fixtures verify that resizing, changing views, GPU quality adaptation and context recovery preserve the live game/state. The deterministic simulation remains independent of display refresh.
- Steady-state graphics samples use 240 warmup render frames then 120 measured frames. Desktop 1440×1000 retained mesh scale1 at711×787: mean frame interval20.8333ms, p95 33.4ms; mean CPU-observed renderer cost6.7653ms, p957.9ms. Mobile 375×667 DPR2 adapted its mesh layer to528×585 (scale 0.8) while the flat maze remained660×731: mean interval 16.6667ms, p95 16.8ms; mean renderer cost5.6702ms, p957.7ms. Both had zero sampled frames above34ms and continued submitting the same actual mesh geometry. Thus this software-rendered desktop run was about48fps; it is not evidence for universal60fps.
- Test environment: headless Chromium 154.0.8037.57, Linux 6.18.55 x86_64/glibc2.41, five logical CPUs, **ANGLE Vulkan SwiftShader software GPU**. Only the normal `--no-sandbox` container flag was used; no GPU/security override was required. GPU timer queries were unavailable, so costs above are CPU-observed render/submission/composite durations, not isolated GPU timings. Physical phones and hardware-GPU performance remain unverified.
- A four-run context-option comparison reduced observed render costs from9.89/7.74ms to6.22/5.06ms when disabling multisampling and drawing-buffer preservation. Immediate readback and visible canvas colors remained correct, including after context restoration. The shader still renders actual 3D solids; adaptive resolution affects only raster size, not geometry or simulation.
